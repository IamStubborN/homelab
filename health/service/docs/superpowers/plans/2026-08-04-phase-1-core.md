# Family Health — Phase 1 (Core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A deployed `health-service` (Rust, MCP) owning a dedicated Postgres, with typed write/read operations, dedup, append-only corrections, audit log, PNG charts, and a shared Hermes skill so both spouses can log and query health data from Telegram.

**Architecture:** Rust workspace mirroring `media-orchestrator` (sea-orm + Postgres, rmcp streamable-HTTP MCP behind axum, per-profile bearer tokens mapped server-side to owner/default person). Hermes does all LLM work (parsing, voice, confirmation cards); the service is deterministic and exposes only typed operations. Deployed as `health-service` + `health-postgres` containers in the `homelab` repo; skill/config land in `hermes-home`.

**Tech Stack:** Rust 1.97 (edition 2024), sea-orm `=2.0.0-rc.42` + sea-orm-migration, rmcp `=3.1.0` (`transport-streamable-http-server`), axum `=0.8.9`, tokio `=1.52.3`, sha2 `=0.11.0`, time `=0.3.53`, uuid, plotters `=0.3.7` + image (PNG), cargo-nextest, mise.

**Spec:** `docs/superpowers/specs/2026-08-04-family-health-system-design.md`

## Global Constraints

- All created folders/files/identifiers are in English; Russian only in user-facing Telegram strings (spec decision 8).
- Source of truth is Postgres; Hermes never edits files/SQL directly — typed MCP operations only (spec decisions 1–2).
- Every mutating operation writes an `audit_log` row in the same transaction (spec §5).
- No physical DELETE anywhere; soft delete via `deleted_at` only (spec §5).
- Corrections are append-only: original values preserved in `corrections` (spec §5).
- Dedup before insert: SHA-256 event hash; duplicate insert is a reported no-op (spec §5).
- No model-supplied identity: bearer token maps server-side to `(actor, via, default_person)` (spec §6).
- `add_medication`, `stop_medication`, `correct_measurement`, `correct_lab_result` require `confirmed: true` (spec §6 confirmation list); Hermes sets it only after the user taps ✅.
- All dependencies pinned `=x.y.z` in `[workspace.dependencies]`, `resolver = "3"`, `edition = "2024"`, `rust-version = "1.97.0"` — copy `media-orchestrator` conventions.
- `mise` is the only dev entry point: `format`, `check`, `lint`, `test`, `test-integration`, `audit`, `build`, `docker-build`.
- No GitHub Actions deployment of household agents (policy in `hermes-home/README.md`).
- Timestamps stored as `timestamptz`; display timezone `Europe/Kyiv`.
- Serde JSON must NOT enable `preserve_order` (dedup hashing relies on sorted keys).
