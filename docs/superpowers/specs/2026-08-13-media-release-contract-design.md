# Media Orchestrator Release Contract Design

## Goal

Keep `media-orchestrator` as a private application repository and `homelab` as
the public deployment repository. Replace implicit sibling-source discovery
with a small, versioned, immutable release bundle that Homelab can validate
without reading or compiling the private Rust checkout.

## Repository boundary

`media-orchestrator` owns source code, migrations, application tests, image and
CLI builds, MCP schema generation, and release-bundle export. `homelab` owns
Compose, runtime secrets, networks, volumes, Hermes configuration, deployment
preflight, and the pinned copy of an exported bundle.

The operator workstation may have both repositories, but scripts must not infer
either repository through `../homelab` or `../../media-orchestrator`. Cross-repo
operations require an explicit path. The Docker host needs only Homelab plus
registry access; it never needs the private application source checkout.

## Release bundle

The producer writes one directory containing:

- `release.json` — schema version 1, application version, source revision,
  source-tree digest, runner-build digest, latest migration, immutable service
  and runner image references, and SHA-256 values for the other bundle files;
- `MCP_SCHEMA.json` — the complete deterministic MCP tool schema generated by
  the media-api test surface;
- `media-capabilities.json` — the canonical ordered tool-name manifest;
- `media-linux-amd64.sha256` — checksum of the CLI artifact used by Hermes.

Image references must contain `@sha256:` followed by 64 lowercase hexadecimal
characters. All digests and checksums use the same lowercase format. Export is
atomic: generation happens in a private temporary sibling directory, and the
destination is replaced only after every validation succeeds.

No registry upload, GitHub release creation, login, or deployment occurs during
export. Those remain explicit operator actions.

## Producer validation

The exporter fails closed unless the Git worktree is clean, both image
references are immutable, the CLI and checksum agree, the MCP schema is freshly
generated, the schema tool names exactly equal `config/media-capabilities.json`,
and all contract hashes match the written files. It reuses existing source and
runner digest functions rather than duplicating their algorithms.

## Homelab consumption

Homelab stores the pinned bundle at `media/release/`. Its capability checker
validates the local bundle, generated Hermes capability documentation, and all
tool references without a `MEDIA_ORCHESTRATOR_DIR`. Deployment preflight reads
the same `release.json` and compares live OCI labels and immutable image
references with it. Missing, malformed, placeholder, mutable, or inconsistent
bundle data is an error.

Until real private images are published, Homelab keeps a sanitized
`media/release.example/` fixture for tests and documents that live promotion is
blocked on registry login and real image digests. It must not invent production
digests.

## Existing deployment script

The guarded deployment implementation remains in the private application
repository for this change. It must require explicit `HOMELAB_ROOT` and
`MEDIA_RELEASE_DIR` values instead of discovering a sibling checkout. Existing
backup, migration, protected-container, rollback, and live MCP gates remain
unchanged. Moving the large guarded workflow between repositories provides no
runtime benefit and is outside scope.

## Testing

Producer tests cover deterministic output, immutable-reference validation,
hash mismatch, dirty source, schema/capability drift, and atomic failure.
Homelab tests cover bundle parsing, missing and malformed fields, mutable image
rejection, hash drift, capability/schema drift, absence of sibling-source
requirements, and live-attestation comparison. Existing complete repository
checks must continue to pass.

## Non-goals

- no new release service or package registry;
- no automatic deployment;
- no secret values in the bundle;
- no change to media runtime APIs, database schema, or Telegram UX;
- no migration of the guarded deployment script into the public repository.
